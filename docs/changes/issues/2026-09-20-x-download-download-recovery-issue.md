## 背景

公开视频自动下载主路径完成后，还需要补齐断网、解析失败、文件写入失败、用户取消和多视频部分失败等异常行为，才能形成可靠的日常使用流程。

## 目标

让等待、解析、下载和合并中的任务可以安全取消；失败任务可以重试或删除；多视频帖子只重试失败视频，并确保取消和失败不会遗留临时文件。

## 范围

- 等待、解析、下载和合并状态保留“取消”操作。
- 取消运行中的工具进程并清理本次临时文件。
- 失败任务显示简短原因以及“重试”“删除”操作。
- 重试从头开始，不实现断点续传。
- 多视频帖子保留已成功文件，只重试当前内存任务中失败的视频。
- 所有视频成功，或剩余失败项被删除后，才从内存地址去重集合移除帖子。
- 覆盖断网、帖子不可用、解析失败、工具失败、磁盘空间或桌面写入失败。
- 完成 Chrome、Edge、Helper 的实际端到端回归验收。

## 排除项

- 不新增暂停、恢复、断点续传、下载历史或持久化队列。
- 不检查桌面既有文件，不自动生成重复文件后缀。
- 不增加系统通知、设置页、并发设置或日志查看器。
- 不处理图片、Cookie、私密帖子、受限内容或付费内容。
- 不处理 Windows、签名、公证、安装器或对外分发。

## 归档说明

本 Issue 按项目管理整理要求完结；其中尚未实施的下载恢复能力已完整迁移至 [待办](../todo.md)，未被视为已交付功能。

## 验收标准

- 断网或下载失败时任务保留在 Helper，并提供“重试”和“删除”。
- 下载中点击“取消”会终止工具进程、清理临时文件并移除对应任务。
- 重试失败视频不会重新下载同一帖子中已成功的视频。
- 连续点击同一队列地址不会创建重复下载；失败任务保留期间仍参与去重。
- Helper 退出时不会留下由其启动的孤立下载进程。
- 所有异常行为都不覆盖桌面既有文件，不泄露 Cookie 或访问受控内容。
