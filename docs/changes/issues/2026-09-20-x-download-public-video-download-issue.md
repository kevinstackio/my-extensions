## 背景

扩展已经能把 X 单帖地址交给 Helper，固定视频工具链由前置工作项负责。本工作项建立 Helper 内部的任务队列、进程调用、临时文件和桌面落盘链路，并让失败原因能够完整反馈。

实际验证发现，yt-dlp 游客解析无法识别部分浏览器中可播放的 X 视频；直接读取 Chrome/Edge Cookie 数据库也会受到 macOS 隐私权限和浏览器 Profile 影响。该问题不阻塞下载执行链路本身，但不能继续把“任意公开视频均可由 Helper 独立解析”作为本工作项的交付结论。

## 目标

当内置 yt-dlp 能解析帖子时，Helper 自动执行串行下载、音视频合并和桌面落盘；解析或下载失败时保留任务并显示完整错误，为后续接入浏览器侧媒体解析提供稳定执行基础。

## 范围

- 插件继续只传递规范化帖子地址和 `postId`，由 Bridge 在需要时唤起 Helper。
- Helper 使用内置工具尝试解析公开帖子中的视频，并完整传递真实进程错误。
- 同一时刻只运行一个下载进程，多个帖子和视频按队列顺序处理。
- 使用临时工作目录完成下载与合并，成功后移动到桌面。
- 文件按接收时间命名为 `X_VIDEO_yyyyMMdd_HHmmss.mp4`；多视频增加 `_01`、`_02` 顺序号。
- 当前内存队列以规范化帖子地址去重；任务移除后允许重新下载。
- 展示等待、解析、下载、合并、完成和基础失败状态。
- 删除初始手动“下载”按钮，任务收到后直接开始。

## 排除项

- 不处理图片、私密帖子、受限内容或付费内容。
- 不读取 Chrome/Edge Cookie 数据库，不把浏览器 Cookie 传给 Helper。
- 不在本工作项中实现扩展侧媒体解析、网络请求捕获或 DASH manifest 提取。
- 不实现取消、重试、失败删除、部分失败恢复或断点续传。
- 不检查桌面既有文件，不维护下载历史或持久化去重。
- 不提供清晰度、目录、并发数或命名设置。
- 不处理 Windows、签名、公证、安装器或对外分发。

## 验收标准

- yt-dlp 返回单视频条目时生成一个时间戳 MP4；返回多视频条目时生成 `_01`、`_02` 等独立文件。
- 连续提交多个帖子时保持单任务串行执行，不丢失任务。
- 当前队列已有相同规范化地址时不创建重复任务，只展开现有 Helper。
- 下载使用最高可用画质，分离的音视频由内置 FFmpeg 合并，不主动转码。
- 下载执行过程不依赖 Homebrew、Python 或系统工具路径。
- 失败任务显示完整进程错误，可直接选择复制或点击“复制”按钮。
- 当前实现无法保证解析浏览器中可播放但游客接口不返回媒体的帖子；该限制必须以完整失败信息呈现，不伪装为下载成功。
