# 改为仅使用页面媒体来源下载 X 视频

## 元信息

- 工作项：`2026-09-21-x-download-media-source-only-download`
- 项目：`x-download`
- 类型：中型任务
- 状态：待用户验收
- 当前阶段：实现与自动化验证已完成，等待 Chrome、Edge 和 macOS Helper 实际验收
- 创建日期：2026-09-21
- 最近更新：2026-09-21

## 背景

现有主路径已经由扩展从 X 页面接口响应中提取完整 DASH、HLS 或 MP4 媒体来源，再交给 macOS Helper 下载。但是扩展未取得媒体来源时，仍会发送只包含帖子地址的请求，并由 Helper 尝试使用 `yt-dlp` 解析 X 帖子 URL。

该帖子地址解析方式已经实际验证不可用，不应继续作为降级能力或未来备选。当前下载过程也只暴露粗粒度状态，最终文件仍保存到桌面，无法清楚表达接收、视频下载、音频下载、合并和保存阶段。

## 目标

让 X Download 只接受扩展从当前 X 页面解析出的完整媒体来源，并由 Helper 使用 `yt-dlp` 与 FFmpeg 完成媒体下载和合并；同时提供分阶段进度与任务总进度，将完成文件固定保存到 `~/Downloads/X Download/`，且不让未完成资源出现在最终目录或因异常长期堆积。

## 范围

- 扩展必须取得至少一个经过校验的 DASH、HLS 或 MP4 来源，才向 Helper 发送下载任务。
- 扩展等待页面媒体来源时显示加载状态；三秒内未取得来源时停止发送，并明确提示“未获取到可下载的视频来源”。
- 删除将 X 帖子 URL 交给 `yt-dlp` 解析的全部代码、协议兼容、模型和测试。
- Native Messaging `mediaSources` 改为必填且非空；扩展、Native Host 与 Helper 统一只接受协议 v2。
- `yt-dlp` 只负责下载扩展提供的完整媒体来源，FFmpeg 继续负责音视频合并和 MP4 封装。
- Helper 任务状态覆盖接收或准备、等待、下载视频、下载音频、合并音视频、保存到下载目录、完成和失败。
- 当前步骤显示对应进度；每条任务同时显示一条按阶段计算、连续且不倒退的总进度条。
- 多视频帖子继续作为一个任务串行处理，并在状态中显示当前视频序号和总数。
- 完成文件固定保存到 `~/Downloads/X Download/`，不得覆盖已有同名文件。
- 下载分片、视频流、音频流、合并中间文件和 `.part` 文件只保存在应用临时任务目录。
- 正常成功、下载失败和可控异常结束时清理对应临时任务目录；Helper 启动时清理上次崩溃、强制退出或断电遗留的 X Download 临时任务目录。
- 更新已有文档中将帖子 URL 解析描述为可用降级路径的过时内容。

## 排除项

- 不移除或替换 `yt-dlp` 与 FFmpeg。
- 不实现严格按全部媒体真实总字节计算的任务总进度。
- 不处理 Cookie、Authorization、浏览器 Profile、私密帖子、受限内容或付费内容。
- 不新增并发下载、暂停、断点续传、任务历史或持久化队列。
- 不在本工作项中实现运行中取消、失败重试、失败删除或多视频部分失败恢复；这些仍属于后续失败恢复 Issue。
- 不调整现有菜单栏 Popover 的整体布局和视觉样式。
- 不处理 Windows、Firefox、Safari、签名、公证、安装器或对外分发。

## 验收标准

- 在能够取得完整页面媒体来源的 X 单帖中点击扩展后，Helper 创建一个任务并开始下载。
- 扩展未取得完整媒体来源时显示明确提示，不联系 Helper，也不创建失败任务。
- 扩展、Native Host 和 Helper 不再接受或执行只包含 X 帖子 URL 的下载请求。
- `yt-dlp` 的输入只包含经过校验的 `video.twimg.com` DASH、HLS 或 MP4 地址。
- Helper 能依次展示接收或准备、下载视频、下载音频、合并、保存等真实状态；当前步骤进度和任务总进度连续且不倒退。
- 多视频帖子在一个任务中串行处理，并显示当前视频序号和任务整体进度。
- 成功文件出现在 `~/Downloads/X Download/`，未完成文件、中间文件和 `.part` 文件不会出现在该目录。
- 成功或失败后对应临时任务目录被清理；Helper 重启后上次异常退出遗留的临时目录也会被清理。
- 已存在的最终文件不会被覆盖。
- Chrome 和 Edge 均能加载稳定开发产物；页面媒体解析到本地文件落盘的完整流程由用户实际验收。
