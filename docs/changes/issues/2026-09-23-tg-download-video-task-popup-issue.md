## 背景

TG Download 当前在 Telegram 媒体预览页内显示下载菜单，并由该菜单承担单次视频下载的加载、成功和失败反馈。下载开始后，菜单的忙碌状态会阻止同一标签页继续发起其他下载；关闭媒体预览后，用户也无法再看到上一项下载的状态。

用户希望在系统文件保存窗口确认保存路径后，用短暂提示替换页面下载按钮，将视频下载任务和进度集中显示在扩展 Popup 中。这样即使关闭当前媒体预览，仍可继续选择其他视频并发下载，同时从工具栏手动打开 Popup 查看仍在进行或已经失败的任务。

## 目标

为 TG Download 增加仅面向视频的内存任务列表和扩展 Popup：保存路径确认后下载按钮变为短暂提示，每个视频独立并发下载；Popup 汇总当前 Telegram 标签页中的活跃与失败任务，显示文件名、下载进度和状态，并提供打开系统 Downloads 目录和清理失败任务的入口。

## 范围

- 仅将视频下载纳入任务系统；图片继续保持当前页面菜单反馈流程。
- 系统文件保存窗口确认后，立即关闭当前视频下载菜单并创建下载任务。
- 视频任务创建后，不主动打开 Popup；用户通过工具栏扩展图标查看下载列表。
- 保存路径确认后，在原下载按钮位置显示“已开始下载，可在扩展中查看进度”约 1.2 秒，再自动淡出。
- 允许同一 Telegram 标签页连续发起多个视频下载，不设置人为队列或并发数量上限。
- 任务状态只保存在对应 Telegram 标签页内容脚本的内存中，不写入扩展存储。
- 增加 Popup，聚合当前可访问 Telegram 标签页中的视频任务并实时显示下载进度。
- Popup 使用固定默认尺寸；任务列表溢出后纵向滚动，无任务时居中显示“没有下载任务”。
- Popup 顶部左侧显示“下载”，右侧依次显示打开 Downloads 目录和清理失败任务按钮，Header 与内容区之间使用分割线。
- 使用用户提供的 `folder-down.svg` 与 `trash.svg`，不显示下载数量角标。
- 下载成功后立即从内存和 Popup 移除；下载失败后保留，直到用户点击清理按钮。
- 视频失败任务保留可读失败原因；至少区分 HTTP 状态、网络请求、媒体读取和本地文件写入失败。
- 文件夹按钮通过扩展下载 API 打开系统默认 Downloads 目录；清理按钮只删除失败任务，不影响下载中的任务。
- 不新增 Telegram 页面内下载浮层；下载列表继续使用现有扩展 Popup。
- 补充任务状态、消息边界和 Popup 纯逻辑的自动化验证，并完成类型检查与 WXT 构建。

## 排除项

- 不改变图片下载流程，也不在 Popup 中显示图片任务。
- 不使用 `storage`、IndexedDB、文件或其他方式持久化任务记录。
- 不保证 Telegram 标签页关闭或刷新后继续下载或保留任务。
- 不增加取消、暂停、重试、重新打开文件、单项删除或历史记录功能。
- 不设置下载队列、串行执行或人为并发上限。
- 不增加工具栏下载数量角标、系统通知或完成记录。
- 不引入 React、新依赖或新的 UI 组件库。
- 不自动化测试 Popup 的视觉、布局、焦点或指针交互。

## 验收标准

- 用户对视频确认系统保存路径后，下载按钮变为“已开始下载，可在扩展中查看进度”提示，约 1.2 秒后自动淡出，下载继续进行。
- 页面不主动打开 Popup；用户点击工具栏扩展图标后可以看到刚创建的视频任务。
- 一个视频仍在下载时，用户可以关闭当前媒体预览、打开另一个视频并立即发起新的下载；两个任务互不阻塞。
- Popup 默认显示为 `360 × 400px`，顶部左侧为“下载”，右侧依次为文件夹和清理按钮，下方有分割线。
- 没有任务时，内容区居中显示“没有下载任务”；任务超过可用高度时只滚动内容区。
- 每个视频任务显示文件名、进度条和百分比或明确状态；无法得到总大小时显示不确定进度。
- 视频失败任务显示 HTTP 状态或“网络请求失败”“读取媒体失败”“无法写入文件”等可读原因，未知原因回退为“下载失败”。
- 下载成功的任务立即自动消失；下载失败的任务保留，点击清理按钮后全部移除。
- 清理按钮不能删除或中断下载中的任务；没有失败任务时不可用。
- 文件夹按钮打开 Finder 中的系统默认 Downloads 目录。
- Popup 关闭再打开后，只要 Telegram 标签页仍存在，下载中的任务和进度仍可恢复显示。
- Telegram 标签页关闭或刷新后，对应的内存任务消失；本期不承诺继续下载。
- 图片下载行为与当前版本一致，不出现在 Popup 中。
- 工具栏不显示下载数量角标。
- 与该行为对应的自动化测试、TypeScript 类型检查和 WXT 构建通过。
- 用户在当前稳定版 Chrome 或 Edge 中确认布局、交互和并发下载行为符合预期。
