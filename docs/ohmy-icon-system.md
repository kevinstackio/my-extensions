# OhMy Icon System · 图标设计规范 V3

## 1 · 定义与适用范围

这是一套个性化单色图标规范，用于 Tabs 网站的图标，并可作为 Kinari UI 的配套图标使用。图标按所表达的含义命名，不绑定产品名称、网站身份或 `ohmy-` 前缀。

- 每个个性化图标只维护一份手绘 SVG 矢量源稿。
- extension、download、photos、bookmark 是同级图标，可以在需要这些含义的界面中使用。
- extension 表达扩展或插件，不承担网站 Logo 职责。
- 网站的插头 Logo 使用独立的 [exts 插头 Logo 与跨平台生成规范](./exts-logo.md)。
- GitHub、Notion、YouTube 等网站图标可以参考 Simple Icons 原图手绘并调整细节，统一大小、颜色与绘制风格；是否带框由用户逐图确认，不按“品牌／非品牌”分类决定。
- 本文替换本地 V2。V3 调整用途、命名、颜色和交付方式，保留原有外框与图案的几何基准；本次不修改已存在的图标资源。

## 2 · 母版坐标系统

| 参数 | 规范值 | 说明 |
| --- | --- | --- |
| SVG 坐标范围 | `1024 × 1024` | 全部正式 SVG 统一为 viewBox="0 0 1024 1024" |
| 基础网格单位 | `64` | 关键尺寸优先落在网格 |
| 几何中心 | `512, 512` | 外框与中央图案共同中心 |
| 坐标原点 | `0, 0` | 画布左上角 |
| 颜色模型 | sRGB | 派生资源保持一致 |

1024 是内部坐标规格，不是固定显示像素。每个图标只交付一份正式 SVG，不写固定 width、height；使用方自行决定显示大小和渲染方式，不额外生成 24×24 接入版。

## 3 · 共同外框

图标可以带框，也可以不带框，具体选择按用户对每个图标的定稿确认，不由品牌身份决定。带框图标复用下列共同外框；无框图标保留完整主体，不添加该外框。外框是绘制风格的一部分，不代表特定产品。

| 参数 | 规范值 | 坐标或比例 |
| --- | --- | --- |
| 外框可见尺寸 | `896 × 864` | 横向略宽 |
| 外框可见边界 | `x 64–960` | `y 80–944` |
| 外侧圆角半径 | `176` | 沿用定稿 |
| 外框厚度 | `56` | 与中央图案线宽分开 |
| 内侧边界 | `x 120–904` | `y 136–888` |
| 内侧圆角半径 | `120` | 外侧半径减外框厚度 |
| 圆角路径 | 三次 Bézier 圆角 | 四角共用确定性路径 |

- 外框不是正方形，中心仍为 `512, 512`；不改用旧版超椭圆。
- 使用外、内两条封闭路径形成复合路径，不保留描边。
- 确认为带框的图标复用同一外框，不按平台或主题重画外框；无框图标不因需要统一风格而被强行加框。
- 图标登记应注明带框或无框。尚未确认的图标，不由代理自行加框、去框或同时制作两套。
- 当前已确认首批 GitHub、Notion、YouTube 均无框，风格为圆润饱满；尚未绘制或完成视觉验收。

## 4 · 中央图案与安全区

| 区域 | 尺寸 | 坐标 |
| --- | --- | --- |
| 硬性安全区 | `640 × 576` | `x 192–832 / y 224–800` |
| 光学中心 | `512, 512` | 几何居中后整体校正 |
| 允许的光学位移 | X/Y 各 `±32` | 只移动完整图案组 |

- 每个图案按视觉重量确定可见尺寸，不统一限制最长边。
- 保持原始比例，不拉伸；内部零件作为锁定组一起移动。
- 登记最终可见边界、宽高和 X/Y 偏移，同一图案所有使用场景复用这些值。

## 5 · 视觉居中

1. 计算全部可见路径的联合边界，将几何中心对齐到 `512, 512`。
2. 检查负空间与视觉重量，必要时对完整图案做不超过 `±32` 的整体校正。
3. 登记最终偏移，不能只凭外接矩形居中，也不为主题或尺寸单独设置偏移。

左右对称图案原则上保持 `X = 0`。拼图凸凹、缺口、箭头、太阳和山的视觉重量都应作为完整构图评估。

## 6 · 图形语言

| 属性 | 规范 |
| --- | --- |
| 中央线性图案粗细 | `84` |
| 中央线性图案端点半径 | `42` |
| 最小可见结构宽度 | `56` |
| 最小封闭孔洞 | `96` |
| 图形间最小距离 | `56` |
| 连接方式 | 自然、连续 |
| 复杂度 | 用必要结构表达一个核心含义 |

- 线性结构采用圆端点和圆连接，实心结构最窄部位不小于 56。
- 手绘完成后保留为真实矢量路径，不能把扫描图或 PNG 嵌入 SVG 作为成品。
- 不增加文字、缩写、拟物纹理、渐变、阴影或立体效果。
- 小尺寸仍应可辨认，视觉效果由用户检查。

## 7 · 单一 SVG 与主题配色

每个图标只维护一份透明背景的单色 SVG。深浅主题共用完全相同的路径、构图、线宽、透明度和位置。

- 矢量源稿使用单一 `currentColor`；实心路径使用 `fill="currentColor"`。
- 网站和 Kinari UI 通过组件的 CSS `color` 控制图标颜色，与文字、选中、禁用等状态配色一致。
- 深浅主题由使用方的颜色配置负责，不分别手绘、上传或维护深色与浅色图标。
- V2 的 `#1C1A15` 与 `#F2EBDC` 不再是图标源文件的强制颜色；使用方可以采用自己的主题色。
- 不同时在图标内部使用两种颜色，不把深浅主题称为两套图标。
- `currentColor` 随组件换色适用于内联 SVG 或 SVG Symbol；通过 `<img>` 引用的外部 SVG 不直接继承页面的 `color`。

## 8 · 基准图案登记

图标名称表达含义，不代表四个独立产品，也不限制后续只能有四个图标。

| 名称 | 中央图案 | 构图规则 |
| --- | --- | --- |
| extension | Extension 拼图轮廓 | 沿用用户提供的拼图参考，不改变凸凹结构 |
| bookmark | 实心书签 | 圆角顶部与居中的底部 V 缺口 |
| download | 单一下箭头 | 保留箭杆、箭头和箭尖 |
| photos | 太阳与双峰 | 一个圆环太阳与一条双峰山线 |

| 名称 | 已登记可见尺寸 | 中心偏移 |
| --- | --- | --- |
| extension | `544 × 544` | `X +24 / Y -21` |
| bookmark | `410 × 490` | `X 0 / Y 0` |
| download | `448 × 533` | `X 0 / Y 0` |
| photos | `624 × 443` | `X 0 / Y -8` |

这些值沿用原定稿在 `1024 × 1024` 母版中的测量值，不表示新的手绘资源已经完成。新增图案应登记自己的尺寸和偏移。

## 9 · 正式交付与参考手绘

| 项目 | 交付约定 |
| --- | --- |
| 正式源稿 | 一份 1024 坐标、透明背景、单色 currentColor 的 SVG |
| Tabs、Kinari UI 或其他使用方 | 直接使用正式 SVG，自行决定显示大小、颜色与接入方式 |
| Iconfont 或其他格式转换 | 使用方按目标工具需要处理，不建立第二份可编辑图稿 |

当前 exts 插头 Logo、favicon 及其应用品牌派生资源按独立 Logo 规范制作；Tabs 中具体网站的图标遵守下列手绘约定。派生文件不作为第二份可编辑源稿。

### Tabs 网站图标的参考手绘

- 原始参考优先使用 [Simple Icons](https://simpleicons.org/) 及其 [SVG 资源仓库](https://github.com/simple-icons/simple-icons)；没有对应图案时使用用户提供的参考。应用接入规则见 [扩展规范](../apps/extension/AGENTS.md)。
- 允许以原图为基础手绘，用一致的视觉大小、单色、圆角、粗细与简化程度调整细节，保留能够辨识具体网站的核心特征；有现成 SVG 不代表不能手绘。
- 有框与无框都是同一图标风格的可选构图。是否带框由用户逐图确认，不规定“品牌全部无框”，也不规定“个性化图标全部带框”。
- 原图作为参考保留，最终仅维护一份确认后的手绘 SVG；登记来源、外框选择、可见尺寸和偏移，不分别维护深浅主题图稿。
- 所有正式 SVG 使用本规范的 1024 坐标系统与单一 currentColor，包括本轮统一风格的书签图标；不为现有页面另做 24×24 或黑色接入版。未调整的既有资源不在本次文档工作中自动转换。
- 统一图形本身的视觉重量与绘制细节，并保持展示尺寸、留白和对齐一致；不通过拉伸强行统一所有 Logo 的长宽比。
- 图稿外框与页面容器边框分别处理：图稿是否带框按定稿决定，页面容器是否有边框按界面设计决定。
- 本次只修订规范；尚未指定各网站的外框选择或手绘定稿，不据此自动批量重绘、加框、去框或替换现有 SVG。

## 10 · SVG、Iconfont 与命名

本节适用于正式 SVG 源稿；具体显示尺寸与接入方式由使用方负责。

- SVG 使用 `viewBox="0 0 1024 1024"`，不固定 `width` 或 `height`。
- 发布时描边转轮廓，合并重叠路径，保留复合路径孔洞。
- 删除文字、位图、滤镜、蒙版、裁剪路径、隐藏节点和画布外节点。
- Iconfont 每个语义图标只上传一个；若上传工具需要纯黑填充，由使用方在上传环节转换，不在源稿目录维护独立上传版。
- 使用字体图标或单色 SVG Symbol 时，由使用方 CSS 控制颜色。

文件与图标名称直接使用小写语义名；多个单词使用连字符。名称示例为 `extension.svg`、`bookmark.svg`、`download.svg`、`photos.svg`，不加 `ohmy-`、产品名或深浅主题后缀。

这些是新资源的命名规则。本次仅更新文档，不重命名归档或正在被应用引用的旧资源。

## 11 · 手绘与交付流程

1. 确认参考图及带框／无框选择；带框时复用共同外框，用矢量路径手绘主体。
2. 按视觉重量定尺寸，在安全区内完成几何与光学居中。
3. 登记可见尺寸、偏移和路径版本。
4. 清理 SVG，确保只使用单一 `currentColor`。
5. 在浅底、深底以及目标使用尺寸检查同一图案的可辨认程度。
6. 交付唯一正式 SVG，由用户检查风格；使用方自行处理显示尺寸及上传、格式转换。

## 12 · 禁止事项

- 改变共同外框比例、曲线、厚度或安全距离。
- 为主题、尺寸或平台重新手绘同一图标。
- 拉伸、拆散或重新排列中央图案以填满画布。
- 把 extension 指定为网站 Logo，或强制图标绑定产品前缀。
- 维护深浅两套 SVG 几何源稿。
- 用渐变、阴影、纹理、额外底板或装饰掩盖形状问题。
- 将 PNG、预览图或 Iconfont 导出文件当作新的编辑源稿。
- 根据“品牌／非品牌”标签擅自决定是否带框，或在用户未确认时批量重绘、加框、去框。

## 13 · 发布检查表

本表用于手绘图标。Tabs 网站图标同时检查第 9 节的来源、逐图外框选择及接入产物规则。

- [ ] 每个图标仅有一份手绘矢量源稿
- [ ] 使用 `1024 × 1024` 画布，带框／无框选择已确认；带框时复用共同外框
- [ ] 使用无产品前缀的语义名称
- [ ] 图案在安全区内，尺寸和偏移已登记
- [ ] 线宽、端点、孔洞和间距符合基准
- [ ] 透明背景、单色 currentColor，主题仅改变使用方颜色
- [ ] 同一图案在浅底、深底和目标尺寸下可辨认
- [ ] 仅维护一份 1024 坐标正式 SVG，无固定宽高及独立接入、上传或深浅主题版本
- [ ] 不包含文字、位图或滤镜等非路径依赖
- [ ] 派生资源来自同一源稿，用户已完成视觉验收
